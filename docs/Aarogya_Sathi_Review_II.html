Problem Statement

Build a mobile health assistant that connects a person's chronic conditions (diabetes, hypertension, asthma) with their local air quality and weather — and gives them advice grounded in ICMR guidelines, not made-up facts. The system must work in Hindi, Marathi, and English. It must run without paid cloud APIs. It must not store health data on external servers.

Objectives

1. Use Google OKF + CRAG to pull answers from ICMR guidelines without hallucination
2. Correlate live AQI (PM2.5, ozone, UV) with the user's conditions for proactive warnings
3. Support Hindi/Marathi via Bhashini — free, government-backed translation
4. Read 23 wearable metrics (steps, HR, BP, glucose, sleep) via Health Connect SDK
5. Keep all health data on-device in SQLite — zero cloud storage, DPDP Act compliant
6. Block emergencies, prescriptions, off-topic queries with a safety router (<100ms)
SDG 3 — Good Health. Preventive NCD guidance in local languages.
SDG 11 — Sustainable Cities. AQI-linked health warnings for urban areas.
SDG 10 — Reduced Inequalities. Works in Hindi/Marathi, not just English.

What Makes Our Retrieval Different — OKF vs Vector RAG

❌ Traditional Vector RAG

  • Take a medical PDF, split it into 500-token chunks
  • Run each chunk through an embedding model
  • Store 1,024-dim vectors in Qdrant or Pinecone
  • At query time, embed the question and find nearest vectors
  • Problem: "metformin dosage" might match a chunk about "medication adherence" instead of the actual dosage table
  • Problem: Tables and numbered lists get broken across chunk boundaries
  • Problem: No way to audit why a particular chunk was retrieved

✓ Google OKF (What We Use)

  • Write each concept as one Markdown file with YAML metadata
  • Link files together with standard [hyperlinks](path)
  • An agent reads index.md and picks which files to open
  • It then reads those files and follows any relevant links inside them
  • Result: "metformin dosage" → agent opens drugs/metformin.md directly — the whole file, not a random chunk
  • Result: Tables, dosage charts, cross-references stay intact
  • Result: Every retrieval is auditable — you can see which files were opened

Google released OKF in June 2026 [3]. We are among the first projects to apply it in a medical AI system. Our bundle has 45 files with 150+ cross-links.

Actual Code — CRAG Pipeline (pipeline.py)

class CRAGPipeline:
    def __init__(self, bundle_path: str):
        self.navigator = OKFNavigator(bundle_path)

    async def run(self, query, profile, aqi_data, wearable):
        state = PipelineState(query=query, profile=profile,
                              aqi_data=aqi_data, wearable=wearable)

        # Node 1: Navigate OKF bundle
        state.retrieved_docs = await self.navigator.navigate(query)

        # Node 2: Grade documents (CRAG)
        state.relevant_docs, state.needs_fallback = \
            await grade_documents(query, state.retrieved_docs)

        # Node 3: Build context prompt
        state.messages = build_context(
            query=query, docs=state.relevant_docs,
            profile=profile, aqi_data=aqi_data, wearable=wearable)

        # Node 4: Generate with LLM
        full_response = await call_llm(state.messages, size="70b")

        # Stream tokens word-by-word
        for word in full_response.split(" "):
            yield word
            await asyncio.sleep(0.02)

What This Code Does

  • Takes a user query + health profile + AQI data + wearable readings
  • Navigates the OKF bundle to find relevant ICMR guideline files
  • Grades each file — throws away irrelevant ones (that's the "Corrective" in CRAG)
  • Builds a system prompt with docs, profile, AQI, and wearable context
  • Calls the LLM and streams words one at a time for real-time display

File: backend/rag/pipeline.py

135 lines · Uses dataclass for state, async generator for streaming. This is the actual code in our repository, not pseudocode.

Health Connect — Wearable Data Integration

Health Connect is Android's unified health API. It reads from Fitbit, Google Fit, Samsung Health, Garmin — all through one SDK.

CategoryData Types We Read
🏃 ActivitySteps, Calories, Distance, Exercise
😴 SleepTotal, REM, Deep, Light, Awake phases
❤️ VitalsHR, Resting HR, HRV, SpO2, BP, Body Temp, Respiratory Rate
🩸 BodyBlood Glucose, Weight, Height, Body Fat %, BMI
🍎 NutritionCalories, Macronutrients

23 data types total. Users without a wearable can manually log BP, glucose, and weight — the app writes these back to Health Connect too.

How It Flows Into AI Context
