Problem Statement

The Crisis

India's preventive healthcare is broken at three levels

63%
Deaths from NCDs
Non-Communicable Diseases like diabetes, CVDs, and COPD cause 63% of all deaths in India — yet preventive infrastructure is near-zero.
  • ICMR-INDIAB: 26.4% urban diabetes prevalence
  • GBD 2019 (The Lancet): NCDs dominate India's mortality
  • WEF: $4.58 Trillion projected economic loss by 2030
↑ Rising year over year
4.2M
Premature deaths from PM2.5
Air pollution causes 4.2 million premature deaths globally. Indian cities consistently breach WHO safe limits by 10-15x.
  • AQLI 2024: Delhi residents lose 11.9 years of life expectancy
  • Lelieveld et al. (Nature 2015): South Asia bears highest burden
  • 200K+ emergency respiratory admissions linked to AQI events
↑ Worsening annually
90%
Excluded from AI health tools
Over 90% of Indians don't speak English as a primary language. Virtually all AI health tools are English-only.
  • Census of India: 22 official languages
  • Existing apps (Practo, Ada Health) English-only
  • Health literacy gaps compound chronic disease outcomes
Not improving

Objectives

Goals

Agentic triage, localized intelligence, and data sovereignty

  1. Build an AI-driven Digital Health Assistant that assesses symptoms using strictly ICMR-grounded clinical guidelines via RAG.
  2. Integrate real-time environmental APIs (WAQI, OpenWeather) to dynamically alter health advice based on localized air quality.
  3. Deliver health intelligence in 22 Indian languages using Bhashini and IndicTrans2 translation pipelines.
  4. Architect a 100% Indian-hosted, DPDP Act (2023) compliant sovereign data ecosystem.
  5. Validate the system's accuracy through established benchmarks (MMed-RAG, CLINIC) before deployment.

Project Scope

Boundaries

Defining the MVP's boundaries and deliverables

In-Scope (Technical Deliverables)

  • Cross-platform app (Flutter) with offline SQLite caching
  • FastAPI async microservices backend with PostgreSQL
  • ICMR-grounded RAG pipeline using BioMistral/Llama 3
  • Real-time WAQI pollution API integration for contextual alerts
  • OCR parsing for physical lab report extraction

Functional Scope

  • NCD-focused triage: Diabetes, CVDs, Respiratory conditions
  • Target users: Urban Indian adults (25-60) with chronic conditions
  • Geo-focus: High-AQI metropolitan areas (Delhi, Mumbai, Pune)

Out-of-Scope

  • Medical diagnoses or prescriptions (regulatory constraint)
  • Hardware wearable integration (Apple Watch, Fitbit)
  • Live ABDM production deployment (sandbox testing only)
  • Acute emergency triage or real-time teleconsultation

Constraints & Assumptions

  • All LLM inference runs on Indian GPU cloud (E2E Networks)
  • User explicitly consents to data processing per DPDP Act
  • API dependencies (WAQI, Bhashini) assumed stable for MVP duration
  • Testing limited to Android platform for initial release

Tools & Technologies

Stack

Full-stack ecosystem for the MVP

Client & Backend

  • PostgreSQL on E2E: Health data never leaves Indian borders

External APIs

  • WAQI API: Real-time global air quality index data
  • OpenWeatherMap: Weather context for health alerts
  • Bhashini API: Govt of India NLP translation service

Feasibility

Viability

Scaling sovereign AI within practical constraints

  1. Compute Cost: 4-bit model quantization on E2E Networks reduces GPU inference costs by ~70% vs AWS/GCP, ensuring financial viability.
  2. Translation APIs: Bhashini and WAQI APIs are public, mature, and well-documented — no need to train from scratch.
  3. Legal Compliance: Zero-knowledge local inference ensures 100% data residency. Architecture inherently meets DPDP Act consent requirements.
  4. Platform: Flutter provides a single-codebase solution for iOS/Android, drastically reducing UI development overhead.
  5. Testing: Established benchmarks (MMed-RAG, CLINIC) provide validated evaluation frameworks for clinical AI safety.
"By using domestic cloud providers and open-source LLMs, we bypass the cost and sovereignty issues of relying on OpenAI/Google APIs entirely." Technical Feasibility Analysis
